Show results from at least two measured runs. A claim without a number is a plan, not a result.

Full marks, one example each: packaging, an artefact that passes a clean reload and an API whose contract tests pass; container, a multi-stage image with a clean scan and a deployment with probes and limits; observability, a dashboard file and redacted logs with a test; sizing, a load test at three rates with the knee named and a cost per 1,000; release, a recorded canary, a recorded rollback within five minutes and a drift report by segment.

Format

8 minutes to present, 4 to answer

1 · The problem

Who, what, why now. One slide.

2 · What you built

Design, decisions, trade-offs. Then the live demo.

3 · What you measured

Baseline, improvement, failures found, what comes next.

Peer feedback. After each talk, everyone writes one strength, one question and one suggestion.
The submission

One public repository, and the command behind every number

  • The service, its artefact and its contract tests
  • A container file and the deployment manifests
  • The dashboard and two alert rules, as files
  • A README: load test against your objective, canary and rollback, drift check
No real personal data. A public repository holds synthetic or public data only, and no key of any kind.

The README is what the assessors read first: every number in it names the command and the file that produced it, as the release logs did on Day 4. Check before the first talk that every repository is public and that its secrets folder is ignored.

During the defence

The assessor breaks one thing; you show how you would know and what you do

For example

A model folder removed, a decision threshold changed, a slow dependency, a wrong image tag.

You show

Which check, metric, alert or trace tells you, in your own running service.

You act

Roll back, fix or explain, and say who you would tell.

Inject the fault during the questions, not the talk. Choose one the participant's own setup can show: a missing model folder (readiness), a changed threshold (label shares), an extra delay in a dependency (traces and latency), or a tag that cannot be pulled (pod events). Score how fast and how calmly they find it, not whether they knew in advance.
